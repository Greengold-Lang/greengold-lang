Greengold vs. C++ and Rust

18 workloads, measured on 9 October 2026. Greengold builds with --release, which keeps bounds checks and integer overflow traps. Kernels that opt out say so: trust skips a bounds check inside unsafe:, and overflow: wrap wraps instead of trapping. JSON and Trees use neither; Word count wraps only in its random-number generator. See benchmarks/README.md for how to read the numbers.

Fibonacci

84% faster

Recursive fib(41). Each program printed 165580141. The Greengold version uses overflow: wrap. This measures one inlining decision: GCC inlines a small recursive function into itself a few levels deep, LLVM (and so Rust) does not, and Greengold clones the body twice before LLVM runs so that it does the same as GCC. It says little about real programs.

GPU matmul

within 2.4%

Inference-style dense layers on the GPU through OpenCL: 4096 token vectors of width 2048 go through 8 layers of f32 weights, each followed by ReLU and requantization to 0..127 as in an int8 model. The OpenCL kernel is the same in all three languages, so this measures the host side (generating 33 million weights, uploading them, driving the queue) more than the language's own code generation. Each program printed 294743112 4035566 127.

Method

How it was measured

  • Timed programs report the median of five runs. The primes drag race is one run of about 20 seconds, scored by completed passes.
  • Memory is peak working set. Compile time and binary size are from the same build.
  • Raw numbers, including every printed output, are in benchmarks/data.json.

Builds and machine

  • g++ -O3 (15.2.0), rustc -C opt-level=3 (1.99.0-nightly, 2026-08-10), gg build --release with Python 3.11.5 and llvmlite 0.42.0.
  • AMD Ryzen 5 5600X, 6 cores and 12 threads, 32 GB DDR4-3600, Windows 11 Pro build 26200.
  • Greengold sources use hot fn, trust, and overflow: wrap where the workload notes say so.
