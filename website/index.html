What the language does

Native code, value types, and no garbage collector. Six choices define how Greengold reads and fails.

Ownership without lifetimes

Parameters say read, lend, or consume. A stored reference is tied to the place it came from. There is no lifetime syntax.

Native speed through LLVM

Release builds keep bounds and overflow checks and still finish within 5% of C++ and Rust, or ahead of both, on 15 of 18 workloads.

Mutability is inferred

Variables can change by default. One that never changes is treated as fixed, and the editor shows it as an inlay hint.

Failures are loud

Integer overflow, division by zero, bad shifts, and out-of-bounds indexes trap, in debug and in --release.

Diagnostics with checked fixes

gg check --json returns stable codes and fixes. A fix marked verified was applied to a copy and made the error go away.

One way to write it

One spelling for each construct, one specification, and a list of rejected forms. People and language models read the same language.

Ownership is three words

The mode is written on the parameter, never at the call.

read

A shared borrow. The function may read, not assign. The caller keeps the value.

lend

An exclusive borrow. The function may change the value in place; nothing else may touch it during the call.

consume

Takes ownership. After the call the argument is gone, and using it again is a compile error.

A bare parameter of a heap type gets its mode from the body: read when the body only reads it, lend when it changes it, consume when it moves it. Write the mode only when you want to pin it in the signature.

Bindings

Variables can change. The ones that don't are marked for you.

There is no var and no mut on locals. Every variable can change. A variable that nothing changes is treated as fixed, and your editor shows the inferred word as an inlay hint.

  • Write fixed to turn the inference into a guarantee.
  • Assigning, lending, or mutating a fixed value is a compile error.
  • Writing var is an error that tells you to delete it.
Diagnostics

Diagnostics with fixes the compiler has tried

Every diagnostic has a stable GGxxxx code, labels for the definition, the move, and the later use, and a list of fixes.

  1. gg check --json returns the same diagnostic as structured data.
  2. The compiler applies each candidate fix to a copy and re-checks it.
  3. Only fixes that made the error disappear are marked verified.

Status

What exists today, and what is outside the safety guarantee.

The toolchain

Version
0.4.1. Download for Windows, Linux, and macOS, or read the source on GitHub.
Compiler
Written in Python. Emits LLVM IR through llvmlite and links with clang or gcc. LLVM is the only backend.
Tools
gg check, run, build, test, fmt, doc, api, bindgen, and a language server with inlay hints.
Self-hosting
Paused. The lexer is written in Greengold; language work happens in the Python compiler for now.

Outside the guarantee

  • unsafe: blocks — pointers are not checked for liveness, alignment, or bounds.
  • trust, which skips one bounds check, in unsafe: or a hot fn.
  • The --unchecked build flag, which removes bounds checks.
  • std.thread, a pthread wrapper with no Send or Share bound.
  • Not supported: dynamic dispatch, lifetime names, storing or returning a slice []T.
